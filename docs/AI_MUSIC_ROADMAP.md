# AI 音乐风格学习与编曲增强 · 总体规划

> **一句话**：不训练大模型，用「语料统计 + 检索增强 + 确定性生成器 + 判别重排」四层，
> 让 AI 编曲在 **日摇 / 英伦摇滚 / 美式 Hardcore / JRPG 配乐** 四类风格上从「和弦对但难听」走向「像人写的原创」。
>
> 本文是这一方向的总纲：结论、架构、数据、已实现部分、路线图、资源与合规。
> 细分文档见文末「文档索引」。

- 状态：P0（语料管线）、P1（画像接入生成器）已实现；P2（检索层）待做
- 适用前提：本地研究/学习，不对外分发语料与模型权重
- 更新日期：2026-11

## 1. 结论先行

### 能做

| 目标 | 手段 | 工期 | 需要 GPU |
| --- | --- | --- | --- |
| 风格「像不像」明显改善 | L1 风格画像（从语料学到的和弦进行/密度/音区/力度分布） | 1~2 周 | ❌ |
| 伴奏不再千篇一律 | L2 片段检索（RAG）：生成前先查真实片段 | 2~4 周 | ❌ |
| 「难听」的候选被淘汰 | 判别器 + 多候选重排 | 1~2 周 | ❌ |
| 演奏感（不再像音源 demo） | 演奏层人性化：语料的力度方差/微时序 | 数天 | ❌ |
| 补新流派语汇 | L3 微调符号模型（LoRA） | 1~3 月 | ✅ 8~12GB |

### 不能做（或代价极高）

- **让模型「涌现」出新的音乐能力**：没有公开证据支持小数据小模型能做到（见 §6）。
- **用 MIDI 语料提升音色/混音/演唱**：那是音频域，MIDI 管不到。
- **把 Suno / Udio 这类音频模型喂 MIDI**：它们吃音频，不吃 MIDI。
- **靠爬虫拿到几十万条合法 MIDI**：现实上限是 1~3 万（见 §4）。
- **多轨自动转录达到可训练质量**：2026 年仍是草稿级（鼓、贝斯可辨，键盘吉他不可信）。

## 2. 目标与四类风格

| 风格 | 参照 | 可形式化的核心特征 |
| --- | --- | --- |
| **日摇** | STRAIGHTENER / ASIAN KUNG-FU GENERATION | 王道进行 `IV-V-iii-vi` 与小室进行 `vi-IV-V-I`；`bVII`/`III` 借用；`add9`/`sus4` 挂留；160–200 BPM 八分扫弦；贝斯八分根音；副歌前 dropout；吉他间奏 |
| **英伦摇滚** | Muse / Coldplay | `add9`/`sus2`/`sus4` 与平行和弦；Mixolydian `bVII`；钢琴 ostinato + 失真反差；Muse 常用 5/4、7/8；Coldplay 明亮大调 + 后段 build |
| **美式 Hardcore / Alt-rock** | 30 Seconds to Mars | 强力和弦 + drop-D 开放弦；小调 `i–bVI–bIII–bVII`；双踩与军鼓连打；副歌大合唱；合成器铺底混在失真墙；quiet verse → huge chorus |
| **JRPG 配乐** | 植松伸夫 / 光田康典 / 菊田裕树 / 門倉聡 | `bVI`/`bVII`/`bIII` 调式交替、`IV→iv` 借用、半音中音关系；16 分琶音 ostinato；弦乐+铜管+合唱+竖琴；**动机主导**（动机 + 模进 + 变奏）；32~64 小节 loop 曲式 |

**四类风格的共同点**：乐队编制 + 强动机旋律 + 段落级动态对比。
**现有生成器的短板**：只有「4~8 小节循环 + 8 个风格预设」，**没有段落概念、没有动机概念**。这是比「缺语料」更根本的问题。

## 3. 系统架构

```
┌─ ① 语料层 ───────────────────────────────────────────────┐
│ GigaMIDI（需申请）· MetaMIDI/Lakh · VGMusic 爬虫          │
│ · 自有 Guitar Pro 转换 · 已有收藏                          │
└──────────────────────┬───────────────────────────────────┘
                       │  规范化 + 质量闸门
┌─ ② 画像层（✅ 已实现）───────────────────────────────────┐
│ scripts/corpus → 风格画像 JSON（分位数 / 分布 / 功能进行） │
└──────────────────────┬───────────────────────────────────┘
                       │
┌─ ③ 检索层（RAG，待做）───────────────────────────────────┐
│ 4/8 小节片段库 · 索引 · search_reference 工具 · 风格 Skill │
└──────────────────────┬───────────────────────────────────┘
                       │  意图 JSON（不含音符）+ few-shot 参考
┌─ ④ 规划层（现有 LLM Agent）──────────────────────────────┐
│ 曲式 / 和弦进行 / 配器 / 动机计划 / 每段织体选择           │
└──────────────────────┬───────────────────────────────────┘
                       │
┌─ ⑤ 实现层（packages/core 生成器，✅ 已参数化）───────────┐
│ 按画像采样参数 + 乐理约束，把意图渲染成音符                │
└──────────────────────┬───────────────────────────────────┘
                       │  4~8 个候选
┌─ ⑥ 判别层（待做）────────────────────────────────────────┐
│ styleScore（硬伤 + 风格贴合）→ 重排 → top-1                │
└──────────────────────┬───────────────────────────────────┘
                       │
        ┌──────────────┴──────────────┐
        │ ⑦ 模型层（可选，补充候选源） │  MIDI-GPT / AMT
        └──────────────────────────────┘
```

**两条铁律**：

1. **④ 的输出里不能有音符。** LLM 擅长「选和弦、定结构、挑织体、编动机」，不擅长「算第 37 拍那个音的时值」。
   现在 `write_notes` 让模型直接写音符，是当前质量天花板的主要来源。
2. **质量由 ⑥ 决定，不由最大的模型决定。** 从 N 个候选里挑出好的，比凭空生成好的容易得多，也更能立刻提升听感。

## 4. 数据层：语料的现实

### 4.1 实测：能爬多少（2026-11）

| 站点 | 实测 | robots 状态 | 能否批量取文件 |
| --- | --- | --- | --- |
| VGMusic | **> 30,000**（SNES 6,708 / NES 4,204 / Genesis 2,413 / PS2 832） | 无 robots（404） | ✅ 可以 |
| BitMidi | **113,229** 条 | `Disallow: /uploads/`，下载链接恰好全在 `/uploads/` | ⛔ 文件被禁，只能抓元数据或联系站方 |
| MidiShrine | — | `Disallow: /` | ⛔ 明确禁止全站 |
| Songsterr | — | robots 返回 403 | ⛔ 拒绝机器人，且无文件可下 |
| Ultimate Guitar | — | ToS 禁止抓取 + 登录墙 | ⛔ 不爬；改走 GP 本地转换 |
| freemidi / kunstderfuge / ichigos | 数千 ~ 万级 | 多数允许 | ⚠️ 页面无直链 `.mid`，需逐站适配器 |

**结论**：能合法批量下载的只有 VGMusic（3 万级）；「几十万」只有 GigaMIDI（210 万，但需申请访问）。

### 4.2 四类风格的可获取量

| 目标 | 可批量获取 | 能直接进语料 |
| --- | --- | --- |
| JRPG 配乐 | VGMusic 子集，**几千** | ~10~20%（大量是钢琴单轨改编） |
| 日摇 | 免费站基本关闭，**百~千级** | 低（多为单轨旋律） |
| 英伦摇滚 / Hardcore | 同类；西方以 Guitar Pro 为主 | 需 `convert-gp.mjs` 转换 |

### 4.3 三条采集路径

| 路径 | 工具 | 说明 |
| --- | --- | --- |
| 数据集 | GigaMIDI（申请）、MetaMIDI、Lakh、NES-MDB、VGMIDI、Slakh、MAESTRO、GMD | 质量最好、量最大，优先 |
| 爬虫 | `scripts/crawl/run.mjs`（robots 遵从 / 限速 / 续跑 / 台账） | 只用于补齐覆盖不到的曲目 |
| 自有 GP | `scripts/crawl/convert-gp.mjs`（alphaTab） | 将 `.gp3/.gp4/.gp5/.gpx/.gp7` 转 MIDI，已用真实文件验证 |

> 音频转录（basic-pitch / MT3 / YourMT3+）只能产出草稿级多轨，仅可用于和声/节奏层面的统计。

### 4.4 质量闸门

**丢弃**：音符 <16、长度 <8 小节、>400 小节、音高越界 >2%、解析失败。
**打标签保留**：`robotVelocity`（力度恒定，不能学演奏层）、`overQuantized`（完全量化）、`noDrums`（多为钢琴改编，学不到配器）、`ghostTracks`、`gmDrumOutOfRange`。

> 经验：**先看 `noDrums` / `robotVelocity` 的占比，再决定这批语料值不值得进管线**——通常会比直觉悲观。

## 5. 学习层：三层路线

### L1 风格画像（✅ 已实现）— 1~2 周，收益最大

从语料抽取**可解释的统计量**，替换生成器里硬编码的常数。

画像字段：
- `tempo` / `timeSignature` / `key`：速度、拍号、大小调比例、主音分布
- `rhythm`：每小节密度、反拍率、网格偏离、swing 比例、时值分布
- `harmony`：和弦变化率、调内率、和弦性质分布、**高频功能进行（罗马数字 bigram）**
- `intervals`：主旋律线音程分布、级进/跳进/重复率
- `texture`：层数、角色占比、每个角色的音区/密度/复调度/力度方差
- `dynamics` / `articulation` / `repetition`：力度、连断、小节与乐句重复率

### L2 检索增强（RAG）— 2~4 周，性价比第二

**术语先对齐**（这三件事经常被混为一谈）：

| 说法 | 实际是什么 | 改权重 | 产生新能力 |
| --- | --- | --- | --- |
| RAG（检索增强生成） | 写之前先查资料，把真实片段塞进上下文 | ❌ | ❌ |
| Skill（Agent 术语） | 一份 markdown 工作流说明书 | ❌ | ❌ |
| Few-shot / in-context learning | 提示里给几个例子照着模仿 | ❌ | ❌ |
| 微调 / 训练 | 改权重 | ✅ | ✅（但要规模） |

**RAG 是「开卷考试」**：翻书能提分，翻书不会让你长出新的脑子。它能给你「像」和「稳」，给不了「涌现」。

**正确用法**：把语料切成 4/8 小节片段建索引，生成时检索 3~5 个同风格真实片段作为参考。
Agent 的职责从「自己写音符」变成「参考真实编曲的织体，调用生成器并调参」——扬长避短。

### L3 模型（可选）— 1~3 月，且要 GPU

| 模型 | 训练数据 | 输出形态 | 适配度 | 建议 |
| --- | --- | --- | --- | --- |
| **MIDI-GPT** | GigaMIDI（210 万，多轨） | 多轨 MIDI，属性可控 | ⭐⭐⭐⭐ | **首选**：先做推理当候选源 |
| **Anticipatory Music Transformer** | Lakh，≤1.28 亿参数 | MIDI，强项 accompaniment / infilling | ⭐⭐⭐ | 次选，需 GPU 推理 |
| **NotaGen** | 160 万 ABC + 9K 古典 | ABC 记谱文本，古典钢琴 | ⭐ | 不建议做一期（形态不匹配） |

> 参考尺度：MIDI-GPT 用 **210 万**条、NotaGen 用 **160 万**份预训练，才做到「风格相似且不逐音抄袭」。
> 本项目手头的量级适合**微调与重排**，不适合从零训练。

## 6. 关于涌现的事实核查

| 说法 | 证据 |
| --- | --- |
| 小模型（<1e8 参数、<1e5 曲目）能产出训练集里不存在的风格组合 | **未找到任何公开证据。** 现有论文最多证明「风格相似 + 不逐音复制」，无组合泛化的 held-out 评测 |
| 符号模型会「记忆」训练集 | **已被实证**：motif 级局部过拟合（高频动机更容易被原样吐出） |
| 训练规模决定成败 | MIDI-GPT 用 210 万条；NotaGen 用 160 万份预训练。门槛在百万级 |

**结论**：

1. **「学习」可以实现**：可计算的文化先验、检索重组、判别式学习——这三件都是真学习。
2. **「涌现」不能承诺**：那是规模带来的能力跳变，几千首数据上不会发生。
3. 但「写出风格对、有原创感的东西」不需要涌现——人类作曲家主要也靠先验 + 重组。

## 7. 生成层：让 LLM 当指挥

### 7.1 四层职责

```
① 检索层  search_reference(风格, 和弦, 情绪) → 3~5 个真实片段摘要 + 风格画像
② 规划层  LLM 只输出结构化意图 JSON（不含音符）
③ 实现层  packages/core 生成器把意图渲染成音符
④ 判别层  styleScore 打分 → 多候选重排 → top-1
```

### 7.2 已实现的参数化（P1）

| 能力 | 实现 |
| --- | --- |
| 和弦进行 | 从画像 `harmony.topProgressions` 的 bigram 随机游走；数据不足回落内置常量 |
| 密度 | 按角色（bass/guitar/keys/drums…）的 `notesPerBar` 换算缩放系数，收敛在 [0.65, 1.5] |
| swing | 用户未显式设置时，采用语料的律动偏移比例 |
| 力度 | 按语料平均力度校准（收敛在 [0.8, 1.2]） |
| 人性化 | 用**语料的力度方差与网格偏离**抖动，不再用固定随机量 |

**零回归**：没有画像时全部回落到中性值，行为与改造前完全一致（有断言锁死）。

### 7.3 待做：段落与动机（优先级最高）

- **段落**：intro / A / B / 副歌 / 间奏 / 大副歌，每段独立能量与配器密度（解决「整首没起伏」）
- **动机**：短动机 → 模进 / 倒影 / 扩缩 / 转调变奏（解决「没有记忆点」）
- 这两项**不依赖语料**，是听感提升最快的一步

## 8. 判别层：重排

### 阶段 A：多候选 + 可解释评分（不需要训练）

```
一次生成 1 份 →  扩展到 4~8 份（不同 seed / 织体 / 密度）
        ↓
硬伤直接淘汰（复用 quality.ts）+ 软指标加权
        ↓
top-1 给用户（或让用户 A/B 挑）
```

评分维度：和声（调外音、平行五八度、变化率偏离）、声部（交叉、越界、间距）、节奏（n-gram 覆盖率、机械度）、织体（同质化、配器常见度）、形式（段落、重复/变化比）、演奏（力度方差、时序偏差）。

### 阶段 B：从偏好数据训重排器

界面加 A/B 按钮 → 偏好对落库 → 训一个小 reranker（或特征加权）。可回滚，风险最低。

### 阶段 C：DPO（可选）

只有偏好数据量足够、且 A+B 已封顶时才做。

## 9. 评估方法

| 类型 | 指标 |
| --- | --- |
| 客观 | 音级直方图 JS 散度、音程直方图、节奏 n-gram 覆盖率、密度分布、声部交叉率、平行五八度率、同质化率、力度/时序分布 |
| 主观 | A/B 盲测偏好率（**>60% 才算有提升**，<55% 视为噪声） |
| 安全 | 记忆化检测：生成片段与训练语料的 n-gram 重合度 |

## 11. 资源与部署

### 11.1 实测数据（本机）

| 指标 | 实测 |
| --- | --- |
| 服务端常驻内存 | **80 MB**（heap 16 MB） |
| 构建产物 | **5.1 MB**（web 2.3 + server 2.8） |
| P1 新增代码 | **24 KB**（1300 行 TS） |
| 语料管线吞吐 | **390 首/秒**，峰值 138 MB |
| 建 1 万首画像 | 约 26 秒，单核 |

### 11.2 GPU 出现在哪

**只有 P5 训练需要 GPU，而且是一次性离线作业**，不是应用的一部分。

| 任务 | 跑在哪 | 资源 | 频率 |
| --- | --- | --- | --- |
| 应用本体 | NAS / 普通机器 | 1 核，80 MB，0 GPU | 常驻 |
| 语料解析 / 画像 / 索引 | NAS 或台式机 | CPU | 一次性 + 增量 |
| 判别器（特征版） | NAS | CPU 微秒级 | 每次生成 |
| **LoRA 微调** | **台式 GPU** | 8~12 GB 显存，5~8 小时 | 一次性 |

- 小模型 LoRA：8~12 GB 显存（3060 12G / 4070 / 3090 / 5090 都够）
- 全量微调 1.3 亿参数模型：16~24 GB
- 电费：满载数小时约 2~3 度电
- 也可租云卡：几元/小时

### 11.3 存储

| 内容 | 占用 |
| --- | --- |
| 镜像 + 构建产物 | ~200 MB |
| 1 万首语料 | ~200 MB |
| 10 万首语料 | ~1.9 GB |
| GigaMIDI 全量 | ~40 GB |
| 画像 / 片段索引 | **< 100 MB**（只有统计量，不含原始音符） |
| LoRA 权重（可选） | 50~500 MB，放训练机，不打包 |

**结论：NAS 可继续部署，不需要 GPU。** 训练时把脚本拷到台式机，产出权重后再拷回。
「应用变大」这件事不会发生——新增的只是数据文件，不是运行时依赖。

## 12. 风险与合规

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 版权 / 许可 | 产品化阻断 | 只做本地研究；原始文件不入库、不打包；保留来源台账 |
| 语料噪声 | 先验被污染 | 质量闸门 + 人工抽检 200 条做金标 |
| 过拟合小语料 | 风格单一 | 画像向通用先验收缩；分来源验证 |
| 工程量失控 | 爬虫写三个月、生成器没改一行 | 按 P0→P5 顺序，每层有验收标准 |
| 回归 | 现有风格变差 | 画像全部 fallback；A/B 开关 |
| 记忆化 | 输出复现原曲 | n-gram 重合检测、移调增强、Top-K |

**法域边界（仅陈述条文，不构成法律意见）**

- **日本**：著作権法第 30 条之 4 允许「情報解析」目的的复制与改编，但附有「不得不当损害权利人利益」的但书；纯粹「欣赏表达」不在其内。文化庁 2024-03-15《AI と著作権に関する考え方について》为官方解释。
- **中国**：《著作权法》第 24 条合理使用不含机器学习专门条款；《生成式人工智能服务管理暂行办法》第 7 条要求训练数据来源合法。
